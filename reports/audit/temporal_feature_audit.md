# Temporal Feature Engineering Audit Report

**Project:** Explainable SME Financial Distress Early-Warning & Risk Intelligence System  
**Audit Scope:** PHASE 5 — Audit of Temporal Feature Engineering  
**Evidence Source:** `src/features/temporal_features.py`, `src/features/financial_features.py`, `src/features/feature_registry.py`, `src/pipeline.py`, unit test suite, and Dataset A panel observations.

---

## 1. Executive Summary: Temporal Engineering Audit

A central hypothesis of this project is that incorporating multi-period financial deterioration trajectories improves forward distress early-warning performance over static cross-sectional classifiers. 

This audit investigates the mathematical validity, temporal leakage safeguards, entity grouping, feature selection rationale, and missing-history handling of the implemented temporal feature engine.

### Key Audit Findings:
1. **Mathematical Directionality & Leakage:** Backward-looking calculations (`lag_1`, `lag_2`, `diff_1`, `roll_mean_2`, `roll_mean_3`, `roll_std_3`, `acceleration`, `dev_from_baseline`) are mathematically sound and strictly backward-looking. Information from $t+1$ is never used to compute features at $t$.
2. **Entity Grouping Protection:** All shifts and rolling windows are partitioned using `.groupby("Company")`. Feature values never cross company boundaries.
3. **Severe Feature Restriction (Partial Implementation):** While Dataset A contains 83 financial indicators (`x1`..`x83`), temporal features are engineered for **only 8 hardcoded features** (`["x1", "x2", "x5", "x10", "x25", "x48", "x64", "x81"]`). The remaining 75 features are included only as static un-lagged values.
4. **Pre-Split Feature Selection Leakage:** The 8 features chosen for temporal expansion were selected based on correlation with the target across the entire dataset prior to partitioning.
5. **Short-History & First-Period Artifacts:** For initial periods ($T=1$), all lag and difference features evaluate to `NaN` and are replaced with training set global medians. For newly entering firms, this replaces genuine baseline uncertainty with static cross-sectional averages.

## 2. Detailed Technical Audit of Implemented Temporal Features

The table below audits every feature family generated by `TemporalFeatureEngine.generate_temporal_features` in `src/features/temporal_features.py`:

| Feature Family | Implemented Formula / Code Logic | Temporal Directionality | Company Boundary Enforced? | Leakage Status | Methodological Assessment |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **Lag-1 (`x_lag_1`)** | `df.groupby('Company')[feat].shift(1)` | Backward ($\le t-1$) | Yes | **Leak-Free** | Valid. Captures previous period baseline level. |
| **Lag-2 (`x_lag_2`)** | `df.groupby('Company')[feat].shift(2)` | Backward ($\le t-2$) | Yes | **Leak-Free** | Valid. Establishes medium-term historical reference. |
| **Period Delta (`x_diff_1`)** | $x_t - x_{t-1}$ | Backward ($t \text{ and } t-1$) | Yes | **Leak-Free** | Valid. Directly measures 1-period change. |
| **Growth Rate (`x_growth_1`)** | $\frac{x_t - x_{t-1}}{\|x_{t-1}\| + 10^{-4}}$, clipped to $[-5, 5]$ | Backward ($t \text{ and } t-1$) | Yes | **Leak-Free** | Partially valid. Epsilon $10^{-4}$ prevents zero division; clipping $[-5, 5]$ prevents explosion. However, for zero-centered ratios, sign reversals in the denominator can produce misleading growth directions. |
| **Acceleration (`x_acceleration`)** | $(x_t - x_{t-1}) - (x_{t-1} - x_{t-2})$ | Backward ($t, t-1, t-2$) | Yes | **Leak-Free** | Valid discrete second derivative. Identifies compounding deterioration momentum. |
| **Rolling Mean ($k=2$)** | `.rolling(window=2, min_periods=1).mean()` | Backward ($t, t-1$) | Yes | **Leak-Free** | Redundant with `(x_t + x_{lag1}) / 2`. Collinear with static and lag-1 features. |
| **Rolling Mean ($k=3$)** | `.rolling(window=3, min_periods=1).mean()` | Backward ($t, t-1, t-2$) | Yes | **Leak-Free** | Valid smoothing of multi-year financial averages. |
| **Rolling Std ($k=3$)** | `.rolling(window=3, min_periods=2).std().fillna(0.0)` | Backward ($t, t-1, t-2$) | Yes | **Leak-Free** | Valid measure of earnings / ratio volatility. Correctly defaults to 0.0 for $N < 2$. |
| **Consecutive Decline (`x_consec_decline_2`)** | $\mathbb{I}(\Delta x_t < 0 \land \Delta x_{t-1} < 0)$ | Backward ($t, t-1, t-2$) | Yes | **Leak-Free** | Valid binary streak feature for variables where lower is riskier. |
| **Baseline Deviation (`x_dev_from_baseline`)** | $x_t - \text{expanding\_mean}(x_{1} \dots x_{t-1})$ | Backward ($t \text{ vs } < t$) | Yes | **Leak-Free** | Implemented as `s.shift(1).expanding().mean()`. Strictly excludes current $x_t$ from baseline. Valid firm-specific normalization. |

## 3. Investigation of Key Methodological Defects

### 3.1 Defect 1: Arbitrary Subsetting of Features for Temporal Expansion
In `src/features/temporal_features.py` (line 12):
```python
self.key_features = key_features or [
    "x1",
    "x2",
    "x5",
    "x10",
    "x25",
    "x48",
    "x64",
    "x81",
]
```
- **The Issue:** Dataset A contains 83 continuous variables (`x1` through `x83`). Only 8 of these 83 variables (9.6%) are given temporal features. The remaining 75 variables have 0 lags, 0 deltas, 0 rolling means, and 0 volatility metrics.
- **Why this happened:** Generating 10 temporal features for all 83 variables would create $83 \times 10 = 830$ features on a training set of only 2,471 rows, risking severe overfitting.
- **The Defect:** Selecting these 8 specific features was performed based on global correlation with the distress target across the entire dataset. This constitutes **pre-split feature selection leakage**.
- **Correction:** The subset of features to be expanded temporally must be determined through automated feature screening (e.g., VarianceThreshold, mutual information, or LASSO) fitted **strictly on the training split** ($T \le 10$).

---

### 3.2 Defect 2: Missing History and First-Period Handling
Because temporal features require historical depth:
- At $T=1$ (or any company's first observation):
  - `lag_1`, `lag_2`, `diff_1`, `growth_1`, `acceleration`, `consec_decline_2`, `dev_from_baseline` are all `NaN`.
- At $T=2$:
  - `lag_2`, `acceleration`, `roll_std_3` are `NaN`.

#### How the Pipeline Handles These `NaN` Values:
In `src/preprocessing/preprocessors.py` (lines 18, 28, 46):
```python
self.imputer = SimpleImputer(strategy="median")
X_imp = self.imputer.fit_transform(X_train)
```
- **Consequence:** For every firm at Period 1, the `NaN` delta ($x_1 - x_0$) is imputed with the *median delta of ongoing firms* from the training set.
- **Problem:** Imputing a non-zero median delta for an enterprise with no recorded history artificially injects phantom momentum into new client observations.
- **Correction:** Missing lags/deltas should be:
  1. Accompanied by explicit missingness indicator masks (`history_length < 2`), or
  2. Imputed with 0.0 for difference/growth features (representing zero observed change), while level lags are imputed with the current level ($x_{lag1} = x_t$).

---

### 3.3 Defect 3: Semantic Fabrication in `FinancialHealthEngine`
In `src/features/financial_features.py` (lines 73–103), the method `compute_for_dataset_a_row` assigns specific accounting categories to four unmasked variables:
- `x48` $\to$ Assigned to "Profitability"
- `x25` $\to$ Assigned to "Liquidity"
- `x64` $\to$ Assigned to "Leverage"
- `x81` $\to$ Assigned to "Solvency"

The method then computes synthetic scores using hardcoded sigmoid transformations:
```python
p_score = 100.0 / (1.0 + np.exp(np.clip(-1.5 * val_x48, -50.0, 50.0)))
l_score = 100.0 / (1.0 + np.exp(np.clip(-1.5 * val_x25, -50.0, 50.0)))
lev_score = 100.0 / (1.0 + np.exp(np.clip(1.5 * val_x64, -50.0, 50.0)))
solv_score = 100.0 / (1.0 + np.exp(np.clip(-1.5 * val_x81, -50.0, 50.0)))
```

#### Evaluation:
- **No Documented Provenance:** In the Kaggle dataset documentation and published literature (Ebrahimi et al.), variables `x1` to `x83` are masked attributes without confirmed accounting item mappings.
- **Fabrication of Diagnostics:** The radar charts and dimensional breakdowns displayed in View 4 of the dashboard rely on these arbitrary mappings. Claiming that `x48` is "Profitability" or that `x25` is "Liquidity" violates academic and research integrity.
- **Correction:** Unless an official data dictionary from the Tehran Stock Exchange dataset authors is verified, these subscores should be presented as **Statistical Factor Clusters** (e.g., "Primary Predictive Factor A", "Deterioration Factor B") or derived via principal component / factor analysis, rather than labeled as canonical balance sheet items.

## 4. Empirical Evaluation of Temporal Features (Ablation Verification)

From the project's empirical ablation experiment (`reports/model_evaluation/ablation_study.csv`), evaluated on the holdout test set (Time 13):

| Experiment | Feature Set | Feature Count | Test ROC-AUC | Test PR-AUC | Test Brier Score | Gain vs Baseline |
| :--- | :--- | :---: | :---: | :---: | :---: | :--- |
| **Exp 1** | Static Financial Features (`x1`..`x83`) | 83 | 0.7787 | 0.1353 | 0.0632 | Benchmark baseline |
| **Exp 2** | Static Features + Lag-1 & Lag-2 | 99 | 0.7428 | 0.1373 | 0.0654 | Marginal PR-AUC gain (+1.5%), ROC-AUC drop |
| **Exp 3** | Static + Lags + Deltas/Growth | 123 | **0.7983** | 0.1729 | 0.0660 | **+27.8% PR-AUC gain**, highest ROC-AUC |
| **Exp 4** | Full Temporal EWS (Lags + Rolling + Streaks) | 163 | 0.7783 | **0.1946** | 0.0626 | **+43.8% PR-AUC gain**, highest PR-AUC |

### Empirical Insights:
1. **Lags alone (Exp 2) are insufficient:** Adding static lagged levels without differences slightly degrades ROC-AUC due to collinearity ($x_t \approx x_{t-1}$).
2. **Difference Deltas (Exp 3) drive major early-warning gains:** Adding period-over-period change ($\Delta x = x_t - x_{t-1}$) delivers the largest single jump in ROC-AUC (from 0.7787 to 0.7983) and a 27.8% boost in PR-AUC.
3. **Full Temporal Dynamics (Exp 4) maximize Precision-Recall:** Rolling volatility and deterioration streaks push PR-AUC to 0.1946 (+43.8% above static baseline).
4. **Conclusion on Temporal Value:** The empirical evidence validates the research hypothesis: **temporal deterioration features substantially improve early warning discrimination over static cross-sectional ratios**.

## 5. Summary of Recommended Upgrades

1. **Formalize Training-Set Feature Selection:** Replace the hardcoded `key_features` list with an automated, cross-validated feature screening step executed strictly within training folds.
2. **Eliminate Redundant Rolling Window ($k=2$):** Drop `roll_mean_2` as it is mathematically collinear with static + lag-1 features.
3. **Improve First-Period Missing Imputation:** For firms at $T=1$, set difference features to 0.0 and add a binary indicator `is_first_observation`.
4. **Replace Fabricated Health Labels:** Rebrand the pseudo-accounting health subscores in `FinancialHealthEngine` to data-driven statistical factor dimensions.
